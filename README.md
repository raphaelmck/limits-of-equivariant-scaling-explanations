# Limits of kernel and representation-based explanations for scaling in equivariant force fields

Analysis code, frozen result tables, figure scripts, and the experiment code for the paper. This
repository contains exactly what the submitted paper's figures, tables, and numerical claims
depend on — nothing exploratory, nothing superseded, no result that isn't reported.

The story is: `code/experiments/` produced `data/`, `code/analysis/` turns `data/` into
`analysis_out/`, and `figures/` is what that becomes.

**What is runnable from a clean clone of this repository:** every table, figure, and number the
paper reports, regenerated from the checked-in data in `data/` by a CPU-only pipeline. No GPU, no
dataset download, no network access, no checkpoint reads. This path is exercised by `make all`
and takes a few minutes on one core. `analysis_out/` is generated by that pipeline and is not
checked in; it does not exist until you run `make analysis`.

**What is not runnable from this repository:** regenerating `data/` itself — the force tangent
kernels, the intervention forward passes, and the matched-compute evaluations. That code is
provided in full under `code/experiments/`, for audit rather than for execution: running it needs
the model checkpoints, the OMol25 splits, `torch`, `fairchem-core==2.14.0`, the upstream model
implementations, and a GPU. It has not been executed from a clean clone of this repository, and
`make` does not invoke it.

The model checkpoints and the OMol25 dataset are not part of this repository; the checkpoints each
result depends on are listed, with their identifying configuration and hash, in
`data/checkpoints.csv`.

## Quick start

```bash
python3 -m venv .venv && .venv/bin/pip install -e .   # numpy and matplotlib
make analysis    # regenerate every derived table into analysis_out/
make validate    # check those tables against the frozen ones in data/
make test        # check the submitted values against those tables
make figures     # render figures/figure1.pdf and figures/figure2.pdf

make check-manuscript TEX=path/to/main.tex   # paper numbers, read out of the LaTeX source
```

`make all` runs the first four. The whole pipeline takes a few minutes on one core.

**What this data does not support** (stated in full in the appendix; summarized here): the
high-order pathway is not shown to explain any scaling-exponent difference or any ell_max=4
advantage; dependence on high-order features is not shown to grow monotonically with compute;
the 102 matched-compute pairs are dense checkpoints from 11 training trajectories, not 102
independent observations; only the *sign* of the low-to-high causal-dependence effect is shown to
replicate across training runs, not its magnitude.

## Layout

```
data/                    frozen inputs: per-configuration arrays, kernel and KRR results,
                         matched pairs, and the checkpoint manifest
code/
  experiments/           the code that produced data/ (audit copy; not run by make)
  analysis/              regenerates analysis_out/ from data/
    claim1/, claim2/     one script per derived table
    figures/             figure rendering, reading only from analysis_out/
    common/              shared analysis functions: bootstrap, interpolation, fitting, metrics
    validate.py          regenerated tables vs. frozen tables
figures/                 the two rendered paper figures, with panel-by-panel provenance
tests/                   paper numbers vs. regenerated tables
analysis_out/            generated by `make analysis`; not checked in
```

## Reproducibility status

Every table and interval this repository reports reproduces exactly: point estimates involve no
randomness and match to 1e-9 relative, and every confidence interval has a documented upstream
bootstrap seed and call structure, so it reproduces bit-exact rather than merely overlapping.
`make validate` checks all of them.

`REPRODUCING.md` describes what would be needed to go further back than the frozen tables, to the
checkpoints themselves, and how the code under `code/experiments/` is tied to the exact revision
that produced them.
