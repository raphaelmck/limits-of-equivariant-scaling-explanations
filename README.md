# Limits of kernel and representation-based explanations for scaling in equivariant force fields

Analysis code, frozen result tables, figure scripts, and the experiment code for the paper.

**What is runnable from a clean clone of this repository:** every table, figure, and number the
paper reports, regenerated from the checked-in data in `data/` by a CPU-only pipeline. No GPU, no
dataset download, no network access, no checkpoint reads. This path is exercised by `make all`
and takes a few minutes on one core.

**What is not runnable from this repository:** regenerating `data/` itself — the force tangent
kernels, the intervention forward passes, and the matched-compute evaluations. That code is
provided in full under `pipeline/`, for audit rather than for execution: running it needs the
model checkpoints, the OMol25 splits, `torch`, `fairchem-core==2.14.0`, the upstream model
implementations, and a GPU. It has not been executed from a clean clone of this repository, and
`make` does not invoke it.

The model checkpoints and the OMol25 dataset are not part of this repository; the checkpoints each
result depends on are listed, with their identifying configuration and hash, in
`manifests/checkpoints.csv`.

## Quick start

```bash
python3 -m venv .venv && .venv/bin/pip install -e .   # numpy and matplotlib
make analysis    # regenerate every derived table into analysis_out/
make validate    # check those tables against the frozen ones in data/
make test        # check every number the paper reports against those tables
make figures     # render figures/figure1.pdf and figures/figure2.pdf
```

`make all` runs all four. The whole pipeline takes a few minutes on one core.

## Layout

```
data/            frozen inputs: per-configuration arrays, kernel and KRR results, matched pairs
pipeline/        the experiment code that produced data/ (audit copy; not run by make)
provenance/      per-file origin, source revision, and checksums for pipeline/, with a checker
manifests/       every checkpoint each result depends on, with configuration and hash
src/             reusable analysis functions: bootstrap, interpolation, fitting, metrics
scripts/claim1/  kernel and scaling tables
scripts/claim2/  intervention and matched-compute tables
scripts/figures/ figure rendering, reading only from analysis_out/
scripts/validate.py  regenerated tables vs. frozen tables
tests/           reported paper numbers vs. regenerated tables
analysis_out/    generated; not checked in
```

## Provenance of the experiment code

Every file under `pipeline/` was copied from the source tree that produced `data/`.
`provenance/pipeline_manifest.json` records, per file, its original path, the source revision it
was taken at, and the SHA256 of both the original and the released copy.

```bash
python3 provenance/check_pipeline.py                      # hashes and headers
python3 provenance/check_pipeline.py --source-root <path>  # also diff against the originals
```

With a source root, the checker compares abstract syntax trees with docstrings removed and the
release's renames undone, so it proves the released copies are *logically identical* to the
originals: comments and docstrings may differ, code may not. All 43 files pass. The four message
strings whose text was rewritten are enumerated in the checker rather than hidden.

`pipeline/model_patch/` holds the complete set of modifications made to the upstream model
implementations. They are additive instrumentation — they expose per-block hidden states and
change no forward computation, prediction, or force output.

## Reproducibility status

Every interval in the paper is regenerated here. Most are bit-exact reproductions: where the
original bootstrap seed and call structure were recorded, re-running reproduces the frozen
interval to better than 1e-9. Four supporting control tables (`dose_response`, `compensation`,
`same_width_control_B`, `run_replication_control_C`) were produced without a recorded seed, so
their intervals are checked for overlap and agreement on whether zero is excluded rather than for
exact equality; their point estimates involve no randomness and are checked exactly. `make
validate` labels each table with which of the two it is.

`REPRODUCING.md` describes what would be needed to go further back than the frozen tables, to the
checkpoints themselves.
